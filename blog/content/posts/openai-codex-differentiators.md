"코덱스"라는 이름은 한 번 조용히 죽었다가, 전혀 다른 물건으로 부활했다. 2021년 깃허브 코파일럿의 엔진이었던 그 모델은 2023년 단종됐고, 2025년 다시 등장한 코덱스는 이름만 같을 뿐 작동 방식 자체가 다르다. 지금 이 이름이 가리키는 건 클로드 코드나 커서와 경쟁하는 클라우드형 코딩 에이전트다. 무엇이 다른지 짚어본다.

## 1. 한 번 죽었던 이름

2021년 공개된 첫 코덱스 모델은 깃허브 코파일럿의 엔진 역할을 했지만, 2023년 3월 23일 오픈AI는 불과 사흘 전 공지와 함께 코덱스 API 서비스를 단종시켰다. 공식 사유는 간단했다 — 범용 모델인 GPT-3.5와 GPT-4가 이미 코덱스보다 코드를 더 잘 작성하게 되면서, 코딩 전용 모델을 따로 유지할 이유가 사라졌다는 것이다. 코덱스는 1년 넘게 무료 베타로 운영되다가 그렇게 조용히 막을 내렸다.

## 2. 2025년, 완전히 다른 제품으로 부활하다

이름이 다시 등장한 건 2025년이다. 이번에는 크게 두 갈래로 나왔다. 하나는 2025년 4월 16일 오픈소스로 공개된 **코덱스 CLI**다. 로컬 컴퓨터에서 실행되며 OS 수준 샌드박싱과 승인 정책으로 제약된 채 지정된 프로젝트 폴더 안에서만 코드를 읽고 고친다. 초기엔 TypeScript/Node.js로 만들어졌다가 이후 Rust로 재작성됐는데, 지금 저장소 코드베이스의 95.6%가 Rust로 짜여 있다. 공개 후 약 15개월 만인 2026년 7월 19일 기준 주간 활성 사용자가 500만 명을 넘었고 깃허브 스타는 9만 9,624개에 달할 만큼 빠르게 자리 잡았다.

다른 하나는 2025년 5월 16일 리서치 프리뷰로 공개된 **클라우드 기반 코덱스**다. ChatGPT Pro·Team·Enterprise 구독자에게 즉시 제공됐고, Plus 구독자에게는 그해 6월 3일부터 열렸다. 이때 함께 공개된 전용 모델 codex-1은 오픈AI의 추론 모델 o3를 소프트웨어 엔지니어링 작업에 맞춰 강화학습한 버전이었다.

## 3. 핵심 차별점 — 로컬이 아니라 클라우드에서, 순차가 아니라 병렬로

여기서 코덱스의 진짜 차별점이 드러난다. 클로드 코드나 커서 같은 도구는 개발자의 로컬 컴퓨터에서 실행되며 단계마다 사용자의 확인을 거치는 방식이 기본이다. 반면 클라우드 코덱스는 저장소가 미리 로드된 완전히 격리된 원격 컨테이너에서 작업을 비동기로 수행한 뒤, 완료되면 변경사항(diff)이나 풀리퀘스트 형태로 결과를 내놓는다. 사용자는 컴퓨터로 다른 일을 하는 동안 백그라운드에서 여러 작업이 동시에 진행되는 걸 지켜볼 수 있다. 실제로 코덱스는 매니저-워커 구조로 최대 8개의 서브에이전트를 병렬로 돌릴 수 있는 반면, 클로드 코드는 여러 에이전트가 태스크 목록을 공유하며 서로 메시지를 주고받는 "에이전트 팀" 구조에 가깝다. 정리하면 코덱스는 속도와 병렬성, 오픈소스 유연성에 무게를 둔 설계고, 클로드 코드는 추론의 깊이와 단계별 감독을 우선하는 설계다.

## 4. GPT-5-코덱스, 사고 시간을 스스로 조절하는 모델

2025년 9월 15일에는 GPT-5-코덱스가 발표되고 API 키 사용자에게는 그달 23일 제공됐다. VS Code 확장, CLI, 클라우드 코덱스 전체에 통합된 이 모델은 GPT-5를 "에이전트형 코딩"에 맞춰 다시 훈련한 버전으로, 짧은 대화형 세션과 장시간 자율 작업 모두에 대응한다. 기존보다 약 25% 빨라졌고, 작업의 복잡도에 따라 사고 시간을 스스로 조절해 단순한 작업은 빠르게, 복잡한 작업은 최대 7시간까지 연속으로 작업을 이어갈 수 있다. 이후로도 GPT-5.2-코덱스, GPT-5.3-코덱스(2026년 2월 5일)로 빠르게 이터레이션을 거듭하고 있다.

## 5. 하나의 이름, 여러 개의 표면

2025년 10월 6일 정식 일반 출시(GA)와 함께 Slack 연동, 코덱스 SDK, 관리자 도구가 추가됐다. 지금 코덱스는 데스크톱 앱, 오픈소스 CLI, VS Code 확장, 깃허브 연동, Slack, iOS 앱까지 여러 표면으로 제공된다.

## 6. 가격 구조의 차별점 — 챗봇 구독에 번들링된 코딩 에이전트

가격 정책에서도 뚜렷한 차이가 드러난다. 코덱스는 ChatGPT 구독(Free, Go 월 8달러, Plus 월 20달러, Pro 월 100달러 또는 200달러)에 사용량이 포함되는 방식이다. 별도로 API 종량제 경로도 있지만, 이 경로는 자동 깃허브 코드리뷰나 Slack 연동 같은 편의 기능이 빠지고 새 모델도 ChatGPT 구독자보다 늦게 받는다. 2026년 4월 2일에는 메시지당 고정 과금 방식에서 API 토큰 사용량 기반 과금으로 가격 정책이 바뀌기도 했다 — 월 10~40세션 정도면 API 쪽이 Plus보다, 50~200세션이면 Pro의 5배 용량 플랜보다 유리하지만 그 이상은 정액제가 유리하다는 분석이 나온다. 앤스로픽의 클로드 코드나 깃허브 코파일럿이 API 토큰이나 좌석 단위 구독에 기반한 것과 달리, 코덱스는 대화형 챗봇(ChatGPT) 구독 안에 코딩 에이전트 사용량을 끼워 넣은 구조라는 점이 근본적으로 다르다.

## 7. "경계가 필요하다"는 보안 철학

코덱스의 모든 샌드박스 모드는 에이전트가 실제로 작업을 실행하는 단계에서 기본적으로 네트워크 접근이 차단된 상태로 시작한다. 클라우드에서는 격리된 컨테이너 자체가 기본적으로 네트워크에 접근하지 못하고, 로컬에서도 기본 네트워크 접근이 없으며 쓰기 권한은 현재 작업 폴더로 제한된다. 의존성을 설치해야 하는 설정 단계에서만 네트워크를 허용하고, 실제 에이전트가 움직이는 단계는 기본적으로 오프라인이다. 오픈AI는 이 설계를 두고 "자율성에는 경계가 필요하다 — 에이전트가 매번 허락을 구하지 않고 스스로 더 많은 일을 하길 원할수록, 그 환경은 더 엄격하게 제한돼야 한다"고 설명한다. 셸 명령을 실행하고 파일을 읽는 에이전트 단계가 프롬프트 인젝션이나 데이터 유출 위험이 가장 큰 지점이고, 대부분의 유출 경로가 네트워크를 필요로 하기 때문에 이 기본값이 가장 중요한 방어선이라는 논리다.

## 8. 벤치마크는 엎치락뒤치락, 그리고 흔들리는 신뢰

성능 수치로 보면 우열이 뚜렷하지 않다. GPT-5-코덱스는 SWE-bench Verified에서 74.5%를 기록했고, GPT-5.2-코덱스는 80.0%로 올라섰지만 같은 시점 클로드 오퍼스 4.5가 80.9%로 근소하게 앞섰다. 2026년 4월 기준 리더보드에서는 클로드 미토스 프리뷰가 93.9%로 1위, GPT-5.3-코덱스가 85%로 2위, 클로드 오퍼스 4.5가 80.9%로 3위였다. 다만 더 중요한 맥락이 있다 — SWE-bench Verified의 파이썬 과제 500개가 벤치마크 공개 이전에 이미 여러 프런티어 모델의 학습 데이터에 포함돼 있었다는 사실이 드러나면서, "처음부터 문제를 푸는 게 아니라 답을 기억하고 있는 것 아니냐"는 지적이 나왔다. 오픈AI는 결국 2026년 초부터 Verified 점수 보고를 중단하고 SWE-bench Pro 사용을 권장하기 시작했다 — 코딩 에이전트 경쟁이 벤치마크 숫자 하나로 쉽게 정리되지 않는다는 걸 보여주는 사례다.

## 9. 결국 경쟁이 아니라 역할 분담으로

실무에서는 이 둘을 아예 경쟁 관계로 보지 않고 나눠 쓰는 경향이 뚜렷하다. 클로드 코드는 개발자가 단계마다 지켜보며 함께 작업하는 페어프로그래밍용으로, 코덱스는 위임한 작업이나 병합 전 리뷰를 백그라운드에서 처리하는 "플릿(fleet)" 용도로 역할이 갈리는 식이다.

## 정리

코덱스라는 이름은 2023년 한 번 조용히 단종됐다가, 2025년 완전히 다른 철학을 갖고 돌아왔다. 로컬에서 단계별로 감독받으며 작업하는 대신, 격리된 클라우드 컨테이너에서 비동기·병렬로 작업을 처리하고 결과만 diff나 PR로 돌려주는 방식이다. 그 차별점은 어느 모델이 벤치마크에서 몇 점을 더 받았는가보다, 어떻게 실행되고(클라우드 병렬 vs 로컬 감독) 어떻게 과금되는가(챗봇 구독 번들링 vs API 종량제)에 있다. 벤치마크 순위가 계속 뒤바뀌고 그 신뢰성마저 흔들리는 지금, 코딩 에이전트 시장은 성능 경쟁보다 이런 구조적 차이를 축으로 재편되고 있다.
